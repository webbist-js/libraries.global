# Design for three million libraries

libraries.global aims to list every library in the world, about 2.9 million of them, so every feature is designed for that size even though the index holds hundreds of records today. In practice: no request, page, build or browser view loads the whole library table. Large tables are walked by keyset (`id > after`), counts come from grouped SQL or `count()`, filtered and geographic questions go to Meilisearch, and outputs that grow with the index (sitemaps, exports, map data) are split or capped. The first review against this target, in September 2026, found that the sitemap stopped at 100,000 libraries and repeated its first 1,000. It also found that the Atlas sends every library to the browser, about 1.8 GB of JSON at full size. The sitemap now serves an index of 10,000-URL files. The Atlas moves to vector tiles plus Meilisearch (`docs/superpowers/plans/2026-09-30-atlas-vector-tiles.md`). We considered designing for the current size and scaling later, and rejected it: loading everything is the easy pattern, it spreads quickly, and the work to undo it grows with every feature built on it.
