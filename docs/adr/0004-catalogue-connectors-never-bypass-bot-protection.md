# Catalogue connectors never bypass bot protection

`@repo/catalogues` queries library service catalogues on behalf of people using the atlas. When a catalogue answers with an anti-bot measure (a JavaScript challenge, an Anubis proof-of-work page, a CDN "Access Denied"), the connector stops and reports `bot_challenge` or `blocked`, and the Catalogue is marked `unsupported` for that operation. We send an honest User-Agent that names libraries.global and links to a page explaining what the bot does. We don't rotate browser User-Agents, solve challenges, or run code the site sends. The upstream project we ported from (LibrariesHacked/catalogues-library) does some of this. We dropped it because running a site's JavaScript with `Function()` would let any compromised catalogue run code on our servers. Beyond that, getting past a block that a library service chose to put up is a poor way for a public atlas to treat the institutions it describes. As a result, some whole systems (Arena ISBN search, Prism, Koha OPAC search as of September 2026) have no live availability. The fix is to ask services or suppliers to allow our User-Agent, or to use official APIs (Koha's public REST API already gives us branches), not to get cleverer at evasion.
