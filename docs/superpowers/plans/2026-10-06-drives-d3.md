# Drives D3: Verify and Whole-Record Drives, Holds and Finishing Touches Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. **Build-only:** this plan has no test steps (see Global Constraints).

**Goal:** the last band of the Noticeboard and Drives spec.

- **Two new kinds of drive:**
  - _Verify_ drives ask helpers to confirm sections that haven't been checked since a date, through the existing "Still right?" view.
  - _Whole-record_ drives fill whatever each library lacks until it reaches a completeness target, through the existing editors.
- **Holds:** "Give me a library" places a 20-minute hold, so two helpers don't fill the same record. Rows someone else holds say "Someone’s on this".
- **Noticeboard ordering:** "Near me" orders the open drives by distance. Signed-in users can narrow them to "Places I follow". The Contribute hub lists drives in those places first.
- **Content and docs:** the ingest READMEs end with a step to propose a drive, the "How drives work" Knowledge article exists, and a finished drive links to its Journal story.

**Architecture:**

- **Shared rules:**
  - `panelCanFill` (`packages/shared-data/drives.ts`, added in D2) widens to verify and record focus. That one change opens them to the builder, to proposals and to the Strapi policy.
  - D1 already wrote `focusFilter`, `focusMatches` and the `verified_<section>_ts` index fields for both kinds.
- **The task panel** keeps its rule from spec §6.1: it hosts existing editors and never builds new ones.
  - The "Still right?" form body is extracted from `LibraryVerify` so the panel can host it.
  - The whole-record checklist opens the `CorrectionEditor` categories that already exist.
- **Holds** are a hidden Strapi ledger, `api::drive-hold.drive-hold`:
  - A unique `(drive, library)` index decides races.
  - Next asks Meilisearch for candidates and tries them in order.
  - A tagged Submission releases its hold when it is created.

**Tech Stack:** TypeScript, Strapi v5 (Document Service; the content-moderation plugin loads from `dist/`), Meilisearch, Next.js 16 RSC.

**Spec:** `docs/superpowers/specs/2026-10-05-noticeboard-and-drives-design.md`:

- §5.1: `verifyBefore` and `recordTarget`, stored in `focus`

Accepted decisions: D1–D15 and OD-1 to OD-8. OD-2 ships holds here.

**Decisions this plan makes where the spec is silent or self-contradictory:**

1. **The task list marks held rows instead of hiding them.** §6.5 lists held libraries among the list's exclusions, but §6.4 shows held rows as "Someone’s on this", which a hidden row can't do. The browse list keeps held rows and disables them. "Give me a library" (`next`) skips them.
2. **Picking a row places a hold too,** not only "Give me a library". Otherwise `next` could hand out a library someone picked by hand.
3. **A helper holds at most one library per drive.** A new hold releases their previous one.
4. **A verify drive's date must be a real date,** and its sections must come from `VERIFY_SECTIONS`. The message stays D1's "Choose the sections to confirm and a date."

**Interfaces:**

  - `baUserId`: string
  - `expiresAt`: datetime

  It is not added to `groups.json`: hidden types are left out of it.

- **`HOT_PATH_INDEXES`:**

```js
index("drive_holds", ["drive_document_id", "library_document_id"], {
  unique: true,
  before: [dedupe("drive_holds", ["drive_document_id", "library_document_id"])],
}),

index("drive_holds", ["ba_user_id"]),
```

- **Drive service** (`HOLD = "api::drive-hold.drive-hold"`, `HOLD_MINUTES = 20`):
  - **`holdLibrary(driveDocumentId: string, libraryDocumentId: string, baUserId: string, now = new Date()): Promise<{ ok: true; expiresAt: string } | { ok: false; reason: "not_open" | "held" }>`**
    1. The drive must be `open`, checked with `documents(UID).findOne({ documentId, fields: ["status"] })`. Otherwise `not_open`.
    2. `strapi.db.query(HOLD).deleteMany({ where: { driveDocumentId, baUserId, libraryDocumentId: { $ne: libraryDocumentId } } })`: one hold per helper per drive.
    3. `strapi.db.query(HOLD).deleteMany({ where: { driveDocumentId, libraryDocumentId, expiresAt: { $lt: now.toISOString() } } })`.
    4. Read the existing row: `documents(HOLD).findMany({ filters: { driveDocumentId: { $eq }, libraryDocumentId: { $eq } }, limit: 1 })`.
       - It's the caller's: `update` it with `expiresAt = now + 20 min` and return ok.
       - It's someone else's: `held`.
    5. Otherwise `create`. A `23505` (`err.code` or `err.nativeError.code`) means `held`.
  - **`releaseHold(driveDocumentId: string, libraryDocumentId: string, baUserId?: string): Promise<number>`:** `deleteMany` with the user in the `where` when given. It returns the count.
  - **`activeHolds(driveDocumentId: string, viewerBaUserId: string | null, now = new Date()): Promise<{ heldByOthers: string[]; mine: string | null }>`:**
    - It reads with knex: `select library_document_id, ba_user_id from drive_holds where drive_document_id = ? and expires_at > ? limit 2000`.
    - It never returns user ids (spec §11).
  - **`runLifecycle`** first runs `strapi.db.query(HOLD).deleteMany({ where: { expiresAt: { $lt: <now − 1 hour> } } })`.
- **Routes** (`drive-public.ts`, `auth: false`; the controller checks `isValidServiceSecret(x-service-secret)` and then `bridgeBaUserId`):

  | Method and path                                       | Handler             | Body                    | Answers                                                                                                                                                                                                                                       |
  | ----------------------------------------------------- | ------------------- | ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | `POST /drives/:documentId/holds`                      | `drive.hold`        | `{ libraryDocumentId }` | 401 without the secret and user; 400 "Invalid library" for a bad id; 404 "Drive not found." for an unknown or `draft` drive; 422 "This drive isn’t open."; 409 "Someone’s on this library."; 200 `{ data: { libraryDocumentId, expiresAt } }` |
