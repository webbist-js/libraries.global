# Drives D1: Board-Run Drives Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Board-run drives work end to end:

- The editorial board creates, schedules, pins and features a drive.
- A cron opens and closes it.
- The Noticeboard and the drive page show progress counted in Meilisearch.
- Contributors fill gaps from an inline task panel, sending ordinary Submissions tagged with the drive.
- Moderators filter the queue by drive.
- Accepted work becomes Drive Credits, which feed a per-drive leaderboard.

**Architecture:**

- **Shared rules:** a pure module, `packages/shared-data/drives.ts`, holds every rule used on both sides: the scope and focus Meilisearch filters, the in-scope predicate, focus matching, validation, the date rule and the progress maths.
- **Strapi:**
  - adds `api::drive.drive` (a JSON `scope` and `focus`, i18n text, lifecycle fields), with public read routes and bridge-gated board routes
  - adds `api::drive-credit.drive-credit`, a hidden ledger
  - adds a `driveDocumentId` on Submissions, checked by the submission policy and credited after approval
  - adds a fetch-based Meilisearch counter for the lifecycle cron
- **UI:**
  - computes display progress with the public Meilisearch search key, using the same shared filters
  - renders the Noticeboard and drive pages
  - hosts existing editors in a task panel

**Tech Stack:** TypeScript, Strapi v5 (Document Service; content-moderation plugin from `dist/`), Meilisearch, Next.js 16 RSC, vitest, Playwright.

- [ ] **Step 3: Implement `packages/shared-data/drives.ts`.**

Rules the code must follow:

- **Quoting:** quote every string with `JSON.stringify`. A list is written `[${items.map(JSON.stringify).join(", ")}]`.
- **`scopeFilter`**, built in this order:
  1. `documentId IN […]` when `libraries` is non-empty. Otherwise the place clauses, `${level}_slug IN […]` for each level that has slugs, in `DRIVE_PLACE_LEVELS` order. Join them with `OR`, wrapped in parentheses when there are two or more.
  2. `libraryType IN […]`, if set.
  3. `source = "…"`, if set.
  4. `completeness < N`, if set (N truncated to an integer).
  5. `created_ts <= <openedAt unix seconds>`, if `openedAt` is valid.
  6. Always `operationalStatus != "permanently_closed"`.

  Join the clauses with `AND`.

- **`focusFilter`**, as the tests show. Verify is `((verified_<s>_ts < T OR verified_<s>_ts NOT EXISTS) OR …)`, joining the per-section groups with `OR` inside one outer pair of parentheses.
- **`driveFilters`**: `todo = \`${scope} AND ${focusFilter(focus)}\``.
- **`libraryInScope`**: the same rules as a predicate. `createdAt` after `openedAt` is out of scope. A missing `createdAt` counts as in scope; Meilisearch excludes it, but the predicate is only used for credit and policy checks on known libraries.
- **`focusMatches`**:
  - First, the "closed or moved" rule: any `kind: "record"` or `library_edit` whose fields include `operationalStatus` or `streetAddress` matches every focus.
  - For `gaps`, each gap maps to how it can be filled:

```ts
const GAP_FILL: Record<GapKey, { kinds?: string[]; fields?: string[] }> = {
  hours: { fields: ["openingTimes"] },
  photo: { kinds: ["photo"], fields: ["uploadedImages"] },
  accessibility: { kinds: ["facilities"], fields: ["accessibility"] },
  contact: { fields: ["website", "phone", "email", "catalogueUrl"] },
  services: { kinds: ["facilities"], fields: ["services", "amenities"] },
  address: { fields: ["streetAddress", "city", "postalCode", "district"] },
  location: { fields: ["lat", "lng"] },
  facilities: {
    kinds: ["facilities"],
    fields: ["accessibility", "services", "amenities"],
  },
  about: { fields: ["summary", "description", "collectionStats"] },
  history: { fields: ["foundedYear", "openedYear"] },
}
```

    A submission matches when its `fields.kind` is in `kinds`, or when it's a record kind (`kind: "record"` or a `library_edit`) carrying one of `fields`.

- For `verify`: a `kind: "verify"` whose sections overlap, or a record touching that section's fields (hours: openingTimes; status: operationalStatus; address: the address fields; contact: website, phone, email).
- For `record`: any `record`, `photo` or `facilities` correction, or any `library_edit`.
- **`validateDrive`**: return the messages in this order, each only when it applies:
  1. "Give the drive a title of 3 to 120 characters."
  2. "Write a summary of 10 to 280 characters."
  3. "Add one to five steps, each under 200 characters."
  4. "Choose one to three gaps to fill." (gaps: 1–3 valid `GapKey`s). For verify: "Choose the sections to confirm and a date." For record: "Set a completeness target between 50 and 100."
  5. "Limit the drive to places or to a list of libraries." (no places and no libraries)
  6. "A list can hold at most 500 libraries."
  7. "Choose a unit."
  8. "The drive must end after it starts."
  9. "A drive can run for at most 90 days." (`endsAt - startsAt > 90 days`)
  10. "Set a goal between 1% and 100%."
  11. "The source link must be a web address." (`whereToLook.url` non-empty and not http(s))
- **`driveDateLabel`**:
  - `closed` and `cancelled` give "Closed {d MMM}", using `closedAt` or else `endsAt`.
  - `scheduled` and `draft` give "Opens {d MMM}".
  - `open`: `days = Math.ceil((endsAt - now) / 86400000)`.
    - `days <= 0`: "Ends today", warn
    - `days <= 7`: "{n} day(s) left", warn
    - `days <= 14`: "{n} days left", plain
    - otherwise: "Ends {d MMM}", plain
  - Format dates with `new Intl.DateTimeFormat("en-GB", { day: "numeric", month: "short", timeZone: "UTC" })`.
- **`driveProgress`**:
  - `done = max(0, total - todo)`
  - `percent = total ? Math.round(done / total * 100) : 0`
  - `goalMet = total > 0 && done / total * 100 >= goalPercent`
