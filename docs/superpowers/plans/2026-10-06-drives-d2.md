# Drives D2: Community Drives Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking. **Build-only:** this plan has no test steps (see Global Constraints).

**Goal:** drives become a community effort.

- Anyone with standing proposes a drive from the builder in proposal mode. Moderators review it in the `index` queue, can move its dates, and approval schedules it.
- Every "propose" entry point is live:
  - the Noticeboard hero and its propose band
  - "Propose as a drive" on each "Gaps worth a drive" row
  - location pages
  - "Propose a drive from these results" on Find libraries
- Drive work is recognised:
  - +2 points per accepted task
  - +25 for each helper with 5 or more accepted tasks when a drive meets its goal
  - +10 for an accepted proposal
  - five drive badges
  - Drives ribbons on the profile
  - a thank-you email when a drive closes
- Drives appear where contributors already are:
  - the homepage
  - the Contribute hub and the header Contribute menu
  - library pages, location pages and Find libraries
  - My submissions

**Architecture:**

- **Shared rules** (`packages/shared-data/drives.ts`) gain the proposal helpers (`proposedDrive`, `panelCanFill`, `gapsFilled`).
- **`@repo/access`** gains the `drive_proposal` Submission type and the `submit.driveProposal` Capability.
- **Strapi:**
  - The content-moderation plugin's policy checks a proposal.
  - Its `updateStatus` creates the drive on approval through `api::drive.drive`'s `createDrive`, inside the approval transaction.
  - A Moderator's date change is stored as `draftData.moderatorEdit`, with the payload hash re-pinned as `setModeratorTarget` does.
  - Recognition lives in the drive service (credit-time points, the close-time finisher bonus and emails) and in the rewards plugin (badges counted from `drive_credits`).
- **UI:**
  - The D1 builder takes a `mode`.
  - Proposals post through a new Next route that reuses the board's body cleaning.
  - Touchpoints are server-rendered reads of the same cached drive list, plus one small client fetch on the `force-static` library page.

**Tech Stack:** TypeScript, Strapi v5 (Document Service; content-moderation and rewards plugins load from `dist/`), Meilisearch, Next.js 16 RSC.

- **Drive service** (`services/drive.ts`):

  - `creditApproval(submission)`:

    - After the loop, if any credit was created, it awards `drive_task_accepted`:

    - It reads `documents(UID).findMany({ filters: { status: { $eq: "closed" }, closedAt: { $gte: <now − 14 days> } }, fields: ["documentId", "title", "slug", "unit", "closedReason", "final"], sort: ["closedAt:desc"], limit: 20 })`.
    - It keeps only drives whose `final` has no `recognisedAt`.
    - For each drive:
      1. **Helpers:** knex `select ba_user_id, count(distinct submission_document_id) as tasks from drive_credits where drive_document_id = ? group by ba_user_id limit 10000`.
      2. **Finisher bonus:** `goalMet = closedReason === "goal"`. For each helper, if `goalMet && tasks >= 5`, award `drive_finished` (25, metadata `{ driveDocumentId, tasks }`). - **Badges** (`rewards/server/services/badges.ts`): `checkAndAward` merges drive counts into `counts` before the definitions are checked, from two queries inside `try/catch` (zeros on failure, for example when a table is missing in tests).

```sql
-- one row
select count(distinct dc.drive_document_id) as credited,
       count(distinct case when d.status = 'closed' and d.closed_reason = 'goal'
                           then dc.drive_document_id end) as finished,
       count(distinct case when dc.filled_gaps like '%,hours,%'
                           then dc.submission_document_id end) as hours
from drive_credits dc left join drives d on d.document_id = dc.drive_document_id
where dc.ba_user_id = ?;

select count(distinct document_id) as started from drives
where created_by_user_id = ? and proposal_submission_document_id is not null
  and status in ('open', 'closed');   -- ? = `ba:${baUserId}`
```
